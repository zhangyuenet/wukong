# 代码规范 (Conventions)

本文档对应 [PLAN.md](PLAN.md) M0 阶段的“确定仓库的目录结构和代码规范”。规范
从简，遇到实际问题再补充。

## 1. 目录结构

```
wukong/                   仓库本身就是 colcon 工作空间
├── docs/                 文档
├── src/                  ROS 2 功能包，每个包一个目录，包名以 wukong_ 开头
│   ├── wukong_flight/    与 PX4 通信、技能库、飞行前检查、执行计划
│   ├── wukong_perception/ 深度图转点云、高度图和屋檐线、体素地图（纯 numpy）
│   ├── wukong_mission/   找房屋和逐站扫描、航线规划、大模型规划、照片判断、任务报告
│   └── third_party/      由 wukong.repos 导入的第三方包（不提交）
├── sim/                  仿真世界、模型、场景（scenarios/）和场景生成、打分脚本
├── config/               跨功能包的配置；真实环境的配置放 config/local/（不提交）
├── scripts/              环境搭建和启动脚本
└── private/              本地私有文件（不提交）
```

功能包自己的默认参数放在包内的 `config/` 目录，随包安装。

一个功能包内部的分层：

| 文件 | 内容 | 是否依赖 ROS |
|---|---|---|
| 逻辑模块（如 `mission.py`） | 状态机、几何计算等纯逻辑 | 否 |
| 接口模块（如 `px4_link.py`） | 话题名、QoS、消息字段的转换 | 是 |
| 节点（`*_node.py`） | 参数、定时器，把两者连起来 | 是 |

纯逻辑不依赖 ROS，这样不用启动仿真也能做单元测试。

## 2. 语言

- **Python（rclpy）**：任务管理、技能、与大模型的交互。迭代快，大模型的 SDK 也
  以 Python 为主。10–50 Hz 的控制环路用 Python 也够用。
- **C++（rclcpp）**：等到出现 Python 跑不动的环节再用，预计是 M4 的深度图处理和
  视觉定位。届时单独建包。

## 3. Python 风格

- 遵循 ROS 2 的 ament 检查：flake8（行宽 99）和 pep257。`colcon test` 会对三个功能包
  运行它们；`sim/` 和 `scripts/` 不是功能包，由 `scripts/check.sh` 用同样的规则检查。
- 多行 docstring 的摘要写在第二行（ROS 的 pep257 规则 D213）。
- 公共函数写类型标注（模块级函数和公共类的方法，参数和返回值；`__init__` 可以不写
  返回值），由 `scripts/check_annotations.py` 检查是否缺失。只为标注才需要的重依赖
  （ROS 节点、anthropic 客户端）放在 `if TYPE_CHECKING:` 里导入，纯逻辑模块运行时
  仍然不依赖它们。
- 每个源文件（Python 和 shell 脚本）开头写版权和许可证，shell 脚本写在 shebang
  之后；空的 `__init__.py` 除外：

  ```python
  # Copyright 2026 Yue Zhang
  # SPDX-License-Identifier: Apache-2.0
  ```

## 4. 注释与文档

- 代码、注释、提交信息用英文。关键的注释可以在英文后附一行中文。
- `docs/` 下的文档用中文；README 中英双语。
- 注释写“为什么”，特别是踩过的坑和与安全相关的取舍，例如
  `mission.py` 里为什么降落前要先刹车。

## 5. 单位和坐标系

- 一律使用国际单位：米、秒、弧度。参数名不带单位后缀时即为国际单位。
- PX4 接口使用 PX4 的本地 NED 坐标系（x 北、y 东、z 向下）。
- 面向用户的参数（航点、高度）使用“北、东、高度”，相对起飞点，高度向上为正，
  在逻辑模块内部换算成 NED。不要让人写负数来表示“向上”。

## 6. 安全相关的编码约定

- 飞行中模式被切走（遥控接管或 PX4 失效保护）时，节点立即停止发指令，绝不抢回
  控制权。
- 每个等待都有超时，超时后的动作要明确：起飞前取消，起飞后先刹车再降落。
- Ctrl+C 在飞行中表示“停下并降落”，不是直接退出。
- 大模型只负责提出计划。计划在起飞前必须通过 `check_plan()` 的几何检查，
  任何来源的计划都不例外。大模型调用不进入飞行控制环路：规划在起飞前完成，
  照片判断在后台线程里进行。
- 仅限仿真的设置（如 `NAV_DLL_ACT=0`）必须在代码注释里写明，并且只出现在仿真
  脚本中。

## 7. 测试

- 纯逻辑用 pytest 写单元测试，放在功能包的 `test/` 目录。
- 涉及飞行行为的改动，除单元测试外，还要在仿真中实际飞一次。
- 运行：`colcon test --packages-select <包名> && colcon test-result --verbose`
- 提交前运行 `./scripts/check.sh`：编译三个包并运行它们的测试，再检查 `sim/` 和
  `scripts/` 的风格、运行 `sim/` 的测试、检查公共函数的类型标注。全部通过才返回 0。

### 7.1 日志和测试遗留文件

开发虚拟机的磁盘只有 78 GB。2026-11-20 一个没关的仿真让 PX4 写出了 44 GB 的
`.ulg`，磁盘写满，虚拟机崩溃。所以日志有硬性上限，测试做完要清理。

**上限**（由 [scripts/clean_logs.sh](../scripts/clean_logs.sh) 执行，可用环境变量调整）：

| 内容 | 位置 | 保留 |
|---|---|---|
| PX4 飞行日志 | `PX4-Autopilot/build/px4_sitl_default/rootfs/log/` | 最新 3 个，总量不超过 1 GB |
| 评测结果 | `log/eval_m2/<时间>/` | 最新 3 次 + 带 `KEEP` 文件的 |
| 任务结果 | `log/missions/<时间>/` | 最新 5 次 + 带 `KEEP` 文件的 + 手动命名的目录 |
| colcon 日志 | `log/build_*`、`log/test_*` | 每类最新 2 个 |
| ROS 2 节点日志 | `~/.ros/log/` | 7 天 |

**自动执行的保护**：

- `sim.sh` 每次启动先运行 `clean_logs.sh`。
- `sim.sh` 运行期间每 30 秒检查一次：当前 `.ulg` 超过 500 MB 或磁盘剩余不足
  10 GB 时，停止 PX4 日志记录（仿真继续）。
- `eval_m2.sh` 结束时运行 `clean_logs.sh`。
- PX4 只在解锁期间记录日志（`SDLOG_MODE=0`，由 `sim.sh` 设置）。

**每次测试结束后**（人和 AI 助手都适用）：

1. 停掉仿真，确认没有残留进程：`pgrep -af 'px4|gz sim|MicroXRCE'` 没有输出。
2. 运行 `./scripts/clean_logs.sh`。
3. 只保留后续开发需要的结果：证明里程碑完成、或要拿来对比的那次运行，放一个
   `KEEP` 文件并写明原因，例如 `echo "M3 passed" > log/eval_m2/<时间>/KEEP`。
   其余的诊断图、中间数据、临时脚本输出，用完就删。
4. 大体积的临时文件（图片、点云、`.npy`）放在 `/tmp` 或 `scratch/`（不提交），
   用完删除，不要散落在仓库里。

- 提交前确认没有违反 [PLAN.md](PLAN.md) 第 10 节的隐私约定。
